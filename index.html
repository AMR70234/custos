Custos turns a Stellar wallet from one all-powerful key into a set of on-chain policies — spending limits, multisig thresholds, and expiring session keys — enforced by a Soroban smart contract, not a promise.

How it works

Three steps, one contract

No custodian, no off-chain rules engine. Everything below happens through the wallet's own __check_auth implementation.

01

Connect & deploy

Connect Freighter, then deploy the wallet contract with your owner keys and approval threshold.

02

Define a policy

Set a daily spending ceiling, a multisig weight, or hand out a time-boxed session key with its own budget.

03

Soroban enforces it

Every transaction is checked against your policies at the protocol level — before it ever executes.

Features

Guardrails, not gatekeepers

Spending limits

A rolling daily ceiling that applies automatically below your approval threshold.

Multisig thresholds

Weighted owner keys; a transaction only clears once enough weight has signed.

Session keys

Scoped, expiring signers for dApps and games — never touch the owner keys.

On-chain enforcement

Rules live inside the contract's auth check, not a backend that can be bypassed.
